# ViewerAtlas Frontend

The ViewerAtlas frontend is a React, TypeScript, and Vite site for exploring the
aggregate community graph produced by the Python pipeline. It reads like a paper:
one serif and one mono, a reading column with margin notes, numbered figures,
and plain tables. It has five pages: overview (`/`), map (`/map`), results
(`/results`), methods (`/methods`), and one page per channel
(`/channel/:id`). The old `/stats` and `/about` paths redirect.

The map and channel charts are drawn on canvas without a charting library. A few
findings (the bot-filter report, the one-channel share, the game and language
split, the early funnel stages) aren't in the public payload, so they're quoted
from the fixed 14-day run in `src/app/lib/snapshot.ts` and marked as a snapshot
wherever they appear. Keep that file in step with the root README's "Example
Results".

## Data Modes

- **Demo mode:** when `VITE_DATA_URL` is unset or unavailable, the app loads
  `src/app/data/demoAtlasData.json`, the pipeline's output for synthetic
  surveys (every channel is an invented `demo_*` login), and displays a visible
  demo-data banner.
- **Aggregate mode:** production builds fetch the same-origin
  `/data/frontend-data.json` export generated by the pipeline.

The map's window picker switches between rolling windows by fetching siblings of
that URL — `/data/frontend-data-14d.json`, `-30d.json`, `-90d.json` — which the
pipeline publishes alongside it. Each is validated on arrival and cached for the
session, so returning to a window already seen costs no request. The window is
global: the results page and the overview describe whichever window the map is showing,
so the site never contradicts itself.

A window the pipeline has not published yet — because collection has not run
long enough to fill it — is still offered, marked pending. Selecting it
replaces the graph with an explanation instead of requesting a file that does not
exist, and the window starts working on its own once the surveys reach back far
enough. The site opens on whichever window the pipeline nominates as default:
the configured canonical window (30 days in production) once it is ready, and
otherwise the widest window that is. Before any full window exists, it opens on
14 days and says there isn't enough data yet.

The picker hides itself entirely when only one window is described — demo mode,
a single-window deployment, or a `VITE_DATA_URL` whose siblings cannot be
derived.

Remote data is shape-validated and size-limited before rendering. Raw chatter
usernames and VOD message content are not part of the public frontend payload.

## Development

Requires Node.js 22 (the CI version; React Router 7 needs at least Node 20).

```bash
npm ci
npm run typecheck
npm run dev
```

`npm run dev` without `VITE_DATA_URL` shows the synthetic demo dataset. To view real
pipeline output locally, copy the exported payloads into the gitignored
`public/data/` folder and point the dev server at them:

```bash
mkdir -p public/data
cp ../twitchiobot/demo_data/data/frontend-data*.json public/data/
VITE_DATA_URL=/data/frontend-data.json npm run dev
```

The synthetic `demo_data/` output comes from
`twitchiobot/scripts/make_demo_data.py`. See
[docs/development.md](../docs/development.md#run-the-pipeline-without-twitch).
[docs/metrics.md](../docs/metrics.md) defines every field the payload carries.

## Production Build

```bash
npm run build
npm run preview
```

The build includes a restrictive script policy, same-origin data loading, route
code splitting, and no public source maps by default. Edge/CDN security headers
should still be verified at deployment time.

## Deployment

`deploy.sh` builds the app and uploads `dist/` to a private S3 bucket intended to
sit behind CloudFront Origin Access Control. Set `S3_BUCKET` (default
`vieweratlas-frontend`) and optionally `DISTRIBUTION_ID` before running it. The
distribution itself is created once by
`twitchiobot/infrastructure/aws/cloudfront-setup.sh`.

The expected production data URL is configured in `.env.production`:

```text
VITE_DATA_URL=/data/frontend-data.json
```

`VITE_SITE_URL`, if set, adds canonical and `og:url` tags for a custom domain.

### Redeploying the frontend overhaul

Only the frontend needs redeploying. The Python exporter change updates a
comment; it doesn't change the payload or layout. Existing `frontend-data*.json`
files work with the new site, and no analysis rerun, container rebuild, schedule
change, or CloudFront configuration update is needed.

From the repository root, use the existing frontend bucket and distribution:

```bash
S3_BUCKET=vieweratlas-frontend DISTRIBUTION_ID=YOUR_CLOUDFRONT_ID bash frontend/deploy.sh
```

Replace `YOUR_CLOUDFRONT_ID` with the existing distribution ID. Override the
bucket if your frontend deployment uses a different name; this is the site
bucket, not the pipeline's data lake. The script installs
dependencies, typechecks, builds, uploads the site, and invalidates `/*` so the
root and cached route responses all load the new version. It preserves the
`data/` prefix and older hashed bundles so open tabs can still load their page
chunks after deployment. Supply `DISTRIBUTION_ID` to request that cache refresh.
[AWS documents the `/*` invalidation path](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/invalidation-specifying-objects.html#invalidation-specifying-objects-paths)
as covering all files in the distribution.

After the invalidation completes, check `/`, `/map`, `/results`, `/methods`, and
a channel page. Verify that live data loads, the 14- and 30-day windows switch,
and the 90-day window shows its pending notice if it hasn't filled yet. Old
`/stats` and `/about` links should redirect to `/results` and `/methods`.
